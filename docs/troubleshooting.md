# 故障排查

> 适用版本：v2.11.0

本页汇总常见报错、任务失败排查、权限、ASR/OCR 和网络问题。部署前的准备见 [部署文档](deployment.md)。

## 日志与排查

### 任务日志

每个任务的详细执行日志保存在两个位置：

| 位置 | 路径 | 保留策略 |
|------|------|---------|
| 数据库 | `task_logs` 表 | 随任务删除而删除 |
| 文件系统 | `db/logs/task_<任务ID>.log` | 受"日志保留天数"控制 |

查看文件日志：

```bash
docker exec subx cat /app/db/logs/task_<任务ID>.log
```

### 任务失败排查步骤

1. **进入任务详情页**：查看错误日志和诊断信息
2. **检查原始响应**：展开"诊断信息"区域，查看 AI 返回的原始内容
3. **检查容器日志**：
   ```bash
   docker compose logs -f subx
   ```
4. **常见失败原因**：

| 错误类型 | 可能原因 | 解决方案 |
|----------|---------|---------|
| 鉴权失败 (401) | API Key 无效或格式错误 | 检查 API Key 是否正确 |
| 速率限制 (429) | 调用过于频繁 | 降低并发数，等待重试 |
| 请求超时 | 网络不通或模型响应慢 | 检查网络，考虑更换模型 |
| 解析异常 | AI 返回格式不规范 | 检查 AI 返回内容，降低 chunkSize |
| 流式请求失败 | 连接中断 | 切换为非流式模式 |

### 校验日志

翻译过程中会输出如下日志：

```
[校验] 块 #1 AI 返回 140/140，有效 140/140，未改动原文: 10 条(将进入核对)
```

- **AI 返回**：AI 实际返回的条目数
- **有效**：被接受的条目数（非空译文）
- **未改动原文**：AI 未翻译的条目（音乐符号、专有名词、繁简同形等），将在核对页中以 `accepted_same` 状态列出

## 常见问题

### 安装与部署

**Q：容器启动后页面无法访问？**

检查端口映射、防火墙、容器是否正常运行：`docker compose ps && docker compose logs subx`

**Q：HTTPS 反向代理后登录异常？**

确保反向代理透传了 `X-Forwarded-Proto: https` 请求头。

**Q：容器内看不到媒体文件？**

- 检查 `docker compose` 中的 `volumes` 挂载是否正确
- 确认填写的是容器内路径（如 `/media/tv`），不是宿主机路径（如 `/volume1/tv`）
- 确认容器用户对目录有读取权限

**Q：提示权限不足 / `SQLITE_CANTOPEN`？**

- 数据目录必须对容器用户可写。镜像启动时会按 `PUID/PGID` 修复 `DB_PATH` 所在目录、`/app/temp` 和 `/models` 权限。
- 默认用户是 `1001:1001`。媒体文件属于其他用户时，把 `PUID`/`PGID` 改成实际所有者。
- 媒体目录默认不做递归 chown；需要时设置 `CHOWN_MEDIA=true`，模型目录可用 `CHOWN_MODELS=true`。
- 也可以在宿主机手动修复：

```bash
sudo chown -R 1001:1001 ./data/db ./data/temp ./data/models
```

- 如果使用 `user:` 覆盖容器用户，入口脚本不会执行 chown，需要自行保证目录权限。

**Q：忘记访问口令怎么办？**

SubX 没有云端账号，也没有“找回密码”后门。确认无法找回时：

1. 停止容器，先备份 `./data/db`。
2. 用 SQLite 工具打开数据库，执行 `DELETE FROM auth; DELETE FROM sessions;`。
3. 重启容器，刷新登录页，重新设置口令。

这样只清掉登录口令和会话，不会删除媒体、字幕、模型、任务历史和翻译记录。PostgreSQL 对数据库执行同样的 SQL 即可。

**Q：镜像太大 / 拉取很慢？**

- 单镜像包含 Python、FFmpeg、Tesseract 语言包、OCR 依赖和内置中文字体，建议至少预留 2–3 GB 磁盘。
- 使用 [`scripts/pull-image.sh`](../scripts/pull-image.sh) 查看 Docker 原生进度；Ctrl+C 暂停后重新执行可续传。
- 配置 Docker Daemon 代理，见[部署文档的下载镜像章节](deployment.md#4-下载镜像进度暂停与代理)。

### ASR 与模型下载

**Q：ASR 服务不可用？**

先看任务日志里的 ASR 地址，连接失败会明确写出“已尝试 http://...”。

单镜像排查顺序：

1. 设置页「语音识别」地址应是 `http://127.0.0.1:8000`，点「使用内置」可以一键恢复。
2. 查看容器日志：

```bash
docker compose logs -f subx | grep -Ei 'ASR|uvicorn|error|traceback'
```

正常应能看到 `starting built-in ASR` 和 `ASR ready`。如果 ASR 进程一启动就退出，日志里会有 Python traceback，常见原因是 CPU 指令集不兼容或依赖缺失。

3. 在容器里直接测健康检查：

```bash
docker exec -it subx curl -fsS http://127.0.0.1:8000/health
```

4. 如果配置了 `ASR_INTERNAL_URL` 或外部 ASR 地址，确认地址真的可达；单镜像会自动尝试内置 `127.0.0.1:8000` 作为兜底。
5. 如果提示“模型未下载”，去设置页「本地模型管理」下载；如果提示 `ECONNREFUSED`，则是 ASR 进程或端口问题，不是模型问题。

连接外部服务时，确认服务已启动且地址正确。

**Q：模型下载失败？**

- 检查容器是否能访问 Hugging Face；国内网络可设置 `ASR_HF_ENDPOINT=https://hf-mirror.com`。
- 在「本地模型管理」填写 HTTP(S) 代理，或设置 `ASR_DOWNLOAD_PROXY`。
- 确认 `./data/models` 可写、磁盘空间足够。
- 代理只支持 `http://` / `https://`，不支持 SOCKS。
- 下载失败后点击「继续」，会从断点续传。

### 翻译相关

**Q：翻译结果全部是原文，没有译文？**

AI 返回了翻译但被校验拒绝。查看任务日志中的"未改动原文"数。如大量条目为原文，检查：
- API Key 对应的模型是否有余额
- 模型是否支持目标语言翻译
- chunkSize 是否过大导致模型输出截断

**Q：翻译后字幕时间轴偏移？**

SubX 保留原始时间轴，不应出现偏移。如确实偏移，可能是原始字幕文件本身的时间轴问题。

**Q：能否只翻译部分字幕？**

目前不支持选择性翻译部分条目。但可以在翻译完成后进入核对页，对不满意的条目单独重新翻译。

**Q：支持哪些 AI 模型？**

所有兼容 OpenAI 接口的模型都可以使用，包括：
- OpenAI：GPT 系列
- DeepSeek：deepseek-chat / deepseek-v3 等
- Gemini（通过兼容接口）
- 第三方代理/中转服务

### 核对页

**Q：翻译完成但核对页没有内容？**

- 「仅译文」或「双语」任务完成后会生成核对记录。
- 「仅原文字幕」任务也会生成原始字幕核对记录。
- 旧任务没有核对记录时，会优先从已导出的 `output_path` 字幕回填，再回退到外挂字幕源文件。
- 任务在翻译完成前失败或取消、且没有可回填字幕时，页面会明确提示“没有可核对的字幕数据”。

**Q：如何修复 AI 翻译"串位"的问题？**

在核对页使用"译文上移"/"译文下移"按钮调整。如果全部偏移了一行，选中偏移起始条目，点"译文下移"。

**Q：核对页的修改会自动保存吗？**

不会自动保存。修改后需点击"保存修改"按钮。但在导出、批量重译前会自动保存。

**Q：为什么核对页能看到 `__SUBX_FMT_1__` 这样的标记？**

这些是系统内部的格式化保护标记（保护 `<i>` 等 HTML 标签在翻译过程中不被 AI 修改）。在最终导出时会自动清除，不会出现在字幕文件中。

### 其他

**Q：Windows Edge 最小化后会自动弹回？**

这是 Edge 与 Vue Router 在 `visibilitychange` 时写入滚动位置有关的兼容性问题。SubX 已加入仅对 Edge 生效的规避补丁；如仍出现，请升级到包含该修复的版本，并确认没有使用旧缓存页面。

**Q：长视频语音识别可以暂停/继续吗？**

可以。ASR 任务会按分段识别并保存检查点：

- 任务页支持「暂停任务」/「继续任务」。
- 暂停会在当前识别分段完成后生效。
- 继续任务会复用已完成的识别分段，只处理剩余分段。
- 失败重试和容器重启后也会复用已有分段。
- 检查点默认保留 168 小时。分段时长、分段重叠和检查点保留时间可在「设置 → 语音识别 → 分段与断点」调整，也可通过 `ASR_CHUNK_SECONDS` / `ASR_CHUNK_OVERLAP_SECONDS` / `ASR_RESUME_TTL_HOURS` 设置默认值。段越短，暂停生效越快，但调用次数更多。

**Q：如何备份数据？**

推荐使用内置脚本，备份数据库、`.secret` 和任务日志：

```bash
npm run backup
# 或指定输出目录
node scripts/backup-sqlite.mjs --out ./backups
```

恢复前请先停止 SubX，再执行：

```bash
npm run restore -- ./backups/subx-2026-01-01T00-00-00-000Z
```

恢复脚本会校验备份数据库完整性，并先把当前数据库另存为 `.pre-restore-*`。完整备份策略、权限和自动备份见[运维与数据管理](operations.md#备份与恢复)。

**Q：升级后设置会丢失吗？**

不会。设置保存在数据库中，只要 `db/` 目录持续挂载就不会丢失。

**Q：支持繁体中文翻译吗？**

支持。设置"目标语言"为 `zh-TW` 即可。但 AI 模型必须支持繁体中文输出。

**Q：支持从视频中提取双语字幕吗？**

SubX 提取的是视频内嵌的单语言字幕。如需双语，选择"双语对照"输出模式，系统会保留原文并在上方/下方添加译文。

**Q：任务日志文件会持续增长吗？**

不会。日志文件、临时文件和翻译缓存受“日志保留天数”控制，默认 7 天自动清理；删除任务或清空历史时也会同步清理对应记录和文件。

**Q：如何提高翻译成功率？**

1. 增大分块大小（如 8000-10000），减少上下文断裂
2. 使用翻译能力更强的模型
3. 对于复杂字幕，翻译完成后进入核对页手动调整
4. 添加术语表改善专有名词翻译质量
